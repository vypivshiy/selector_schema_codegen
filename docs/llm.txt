# ssc_codegen — KDL Schema DSL v2.1 Reference for LLMs

ssc_codegen is a code generator for web scraping parsers.
Input: .kdl schema files describing HTML extraction rules.
Output: parser code for Python (bs4, lxml, parsel, selectolax) and JavaScript (DOM API).

Pipeline: .kdl schema -> kdl parser -> AST -> linter -> converter -> output code

## File structure

A .kdl file contains module-level declarations and struct definitions.

Module-level: import, define, json, struct.

## import

```kdl
import "./shared.kdl"
import "./shared.kdl" { Book PriceTransform }
```

Path is relative to current file. Transitive. Cyclic imports forbidden.

## define

Names must be UPPER_CASE: `[A-Z_][A-Z0-9_-]*`.

Scalar (substituted into arguments):
```kdl
define BASE-URL="https://example.com/{{}}"
define RE-PRICE=#"(\d+(?:\.\d+)?)"#
```

Scalar define values can reference other defines via `{{NAME}}` (UPPER_CASE).
Lowercase `{{name}}` in define values are left as-is — they become @request placeholders.

Block (expanded as pipeline operations):
```kdl
define EXTRACT-HREF {
    css "a"
    attr "href"
}
```

## struct

```kdl
struct Name { ... }                    # item (default)
(list)struct Name { ... }              # list
(dict)struct Name { ... }              # dict
(table)struct Name { ... }             # table
(flat)struct Name { ... }              # flat
(rest)struct Name { ... }              # rest (API client)
(raw)struct Name { ... }               # raw (plain-text, no HTML parser)
```

The old property syntax `struct Name type=list { ... }` still works but prefer the prefix form.

### Struct types

- item (default) -> dict. No required special fields.
- list -> list[dict]. Requires: @split-doc.
- dict -> dict[str, any]. Requires: @split-doc, @key, @value.
- table -> dict. Requires: @table, @rows, @match, @value.
- flat -> list[str]. No required special fields. Optional: keep-order=#true.
- rest -> typed REST client class. Body allows ONLY @doc, @request, @error. Requires: at least one @request with name= and response=.
- raw -> plain-text parser. No HTML backend. The document is a plain `str`; fields accept STRING directly. HTML operations (css, xpath, text, attr, raw) are forbidden. Auto-detects ITEM vs LIST from `@split-doc` presence. Supports `@request`/`fetch()`, `@init`, `@pre-validate`, `@check`.

### Special fields

- @doc — documentation string
- @request — optional HTTP constructor (see section below)
- @pre-validate — validate document before parsing; raises error on failure
- @init — pre-compute and cache values; referenced via @name in fields
- @split-doc — split document into items (list, dict, raw with auto-LIST)
- @key — key extraction for dict
- @value — value extraction for dict and table
- @table — table element selector
- @rows — table rows selector
- @match — extract key from row for comparison

- @check <name> — boolean check method; runs pipeline on document, returns bool
  Pipeline must contain `to-bool`. Use `fallback` for error recovery.
  ```kdl
  @check is-main {
      assert { css ".main" }
      to-bool
      fallback #false
  }
  ```
  Generated as a public method: `is_main(self) -> bool` (Python), `isMain()` (JS).
  Called manually before `parse()` to check if the document matches expected structure.

### Regular fields

```kdl
title { css "h1"; text; trim }
link { css "a"; attr "href" }
books { nested Book }
```

### (raw)struct — plain-text parsing

For documents that are NOT HTML (JS files, URL strings, text data).
No HTML parser backend — the document is a plain `str`.

```kdl
// Extract URL from a <script> tag's JS content
(raw)struct PlayerScript {
    playlist_url {
        re #"file:\s*[\"']([^\"']+)[\"']"#
    }
}

// Parse URL query params via composed string ops
(raw)struct AnimeParams {
    dubbing_code {
        split "?"
        index 1
        split "&"
        filter { starts "dubbing_code=" }
        index 0
        rm-prefix "dubbing_code="
    }
}

// Split text into lines (auto-LIST via @split-doc)
(raw)struct PlaylistLines {
    @split-doc { split "\n" }
    url { trim }
}

// Fetch a JS file, parse as raw text
(raw)struct RemoteScript {
    @request "curl {{script_url}}"
    file_path {
        re #"file:\s*[\"']([^\"']+)[\"']"#
    }
}
```

Rules:
- Fields accept STRING directly (document is already a string).
- HTML operations (css, css-all, xpath, xpath-remove, text, attr, raw) are **forbidden** — lint error.
- ITEM/LIST auto-detected: `@split-doc` present → LIST, absent → ITEM.
- String ops (`re`, `re-all`, `split`, `fmt`, `trim`, `filter`, etc.) work as first operation.

## Pipeline operations

Pipeline is a chain of operations. Initial type is DOCUMENT (or STRING for raw structs, or @init value type).

### Selectors

- css <query>: DOCUMENT -> DOCUMENT
- css-all <query>: DOCUMENT -> LIST_DOCUMENT
- css-remove <query>: DOCUMENT -> DOCUMENT
- xpath <query>: DOCUMENT -> DOCUMENT
- xpath-all <query>: DOCUMENT -> LIST_DOCUMENT
- xpath-remove <query>: DOCUMENT -> DOCUMENT

Alternative selector form (pattern-match, ordered fallback):
- css { <query1>; <query2>; ... } (or multiline children)
- css-all { <query1>; <query2>; ... }
- xpath { <query1>; <query2>; ... }
- xpath-all { <query1>; <query2>; ... }

Pattern-match rules:
- Use either one argument or block children, not both.
- Block form requires at least 2 selectors.
- Try selectors in order; use first non-empty result.
- If all selectors are empty, behavior is same as a failed single selector.
- css-remove/xpath-remove do not support block pattern-match form.

### Extract

- text: DOCUMENT -> STRING, LIST_DOCUMENT -> LIST_STRING
- raw: DOCUMENT -> STRING, LIST_DOCUMENT -> LIST_STRING
- attr <name>: DOCUMENT -> STRING, LIST_DOCUMENT -> LIST_STRING
- attr <name1> <name2> ...: DOCUMENT -> LIST_STRING, LIST_DOCUMENT -> LIST_STRING

### String operations (support map semantics: STRING and LIST_STRING)

- trim [chars]
- ltrim [chars]
- rtrim [chars]
- normalize-space
- fmt <template> (template contains {{}} placeholder or scalar define name)
- repl <old> <new>
- repl { <old1> <new1>; <old2> <new2> }
- lower
- upper
- rm-prefix <substr>
- rm-suffix <substr>
- rm-prefix-suffix <substr>
- unescape
- split <sep>: STRING -> LIST_STRING
- join <sep>: LIST_STRING -> STRING

### Regex

- re <pattern>: STRING -> STRING (requires exactly one capturing group)
- re-all <pattern>: STRING -> LIST_STRING (requires exactly one capturing group)
- re-sub <pattern> <repl>: STRING -> STRING

Note: `re` emits a runtime helper (`std_re_search` in Python, `_stdReSearch` in JS) raising `SscRegexError` on no-match, with a default message of `<file.kdl>:<line>:<col> re-match failed at <Struct>.<field> pattern=<pattern>`. Consumer code can catch via `except SscRegexError` (Python) or `try { ... } catch (e) { if (e instanceof SscRegexError) ... }` (JS). Caught by `fallback` when present.

### Array

- index <i>: LIST_* -> scalar
- first: LIST_* -> scalar (alias for index 0)
- last: LIST_* -> scalar (alias for index -1)
- slice <start> <end>: LIST_* -> LIST_*
- len: LIST_* -> INT
- unique: LIST_STRING -> LIST_STRING

### Conversions

- to-int: STRING -> INT, LIST_STRING -> LIST_INT
- to-float: STRING -> FLOAT, LIST_STRING -> LIST_FLOAT
- to-bool: any scalar -> BOOL

### Structured

- nested <StructName>: DOCUMENT -> NESTED (terminal type)
- jsonify <SchemaName> [path="..."]: STRING -> JSON (terminal type)

### Parser contract (pipeline ops)

Pipeline operations emit ERROR diagnostics instead of raising exceptions when
misused. Two guard classes are enforced centrally in `core/expressions.py`
before the per-op handler runs:

- **E100 "requires a preceding operation"** — when an op that reads
  `parent.body[-1]` is used at the start of an empty pipeline. Covers:
  `trim`, `ltrim`, `rtrim`, `normalize-space`, `fmt`, `repl`, `lower`,
  `upper`, `rm-prefix`, `rm-suffix`, `rm-prefix-suffix`, `unescape`, `re`,
  `re-sub`, `re-all`, `to-bool`, `to-int`, `to-float`, `split`, `join`,
  `fallback`.
- **E001 "requires N argument(s), got M"** — when an op is invoked with
  fewer positional args than its handler reads without bounds-checking.
  Covers: `css-remove`, `xpath-remove`, `attr`, `fmt`, `rm-prefix`,
  `rm-suffix`, `rm-prefix-suffix`, `split`, `join`, `re`, `re-all`,
  `re-sub`, `index`, `slice`, `jsonify`, `nested`.

Block-form selectors (`css`, `css-all`, `xpath`, `xpath-all`) and the
`repl` map form accept either a single arg OR a children block — the
argument-count guard does not apply to them.

### Control

- filter { predicates... } — filter lists by predicates, LIST_* only
- assert { predicates... } — validate without changing value; raises SscAssertionError on failure (caught by fallback if present)
- assert "message" { predicates... } — assert with custom error message; default message is `<file.kdl>:<line>:<col> assertion failed at <Struct>.<field>` (or `<Struct>.@pre-validate` inside `@pre-validate`)
- match { predicates... } — select table row, must be first op in table fields
- fallback <value> — default value on error; fallback #null makes type optional
- fallback {} — empty list fallback, LIST_* only
- @name / self name — reference @init value (self is deprecated)

Note: `assert` emits a runtime helper (`std_assert` in Python, `_stdAssert` in JS) raising `SscAssertionError`. Unlike Python's `assert` keyword, this is **not** stripped by `python -O`. Consumer code can catch via `except SscAssertionError` (Python) or `try { ... } catch (e) { if (e instanceof SscAssertionError) ... }` (JS).

## Type system

Scalar: DOCUMENT, STRING, INT, FLOAT, BOOL, NULL, NESTED, JSON
List: LIST_DOCUMENT, LIST_STRING, LIST_INT, LIST_FLOAT
Optional: OPT_STRING, OPT_INT, OPT_FLOAT
Auto: AUTO, LIST_AUTO (internal, for type inference)

NESTED and JSON are terminal — pipeline ends after nested/jsonify.
fallback #null converts STRING->OPT_STRING, INT->OPT_INT, FLOAT->OPT_FLOAT.

## Predicates

Used inside filter, assert, match containers.
Logic containers: not, and, or.

### String predicates (filter, assert, match)

- eq <value...> — equals any
- ne <value...> — not equals any
- starts <value...> — starts with any
- ends <value...> — ends with any
- contains <value...> — contains any
- in <value...> — equals one of
- re <pattern> — matches regex

### Attribute predicates (filter, assert; not match)

- has-attr <name...>
- attr-eq <attr> <value...>
- attr-ne <attr> <value...>
- attr-starts <attr> <value...>
- attr-ends <attr> <value...>
- attr-contains <attr> <value...>
- attr-re <attr> <pattern>

### Text predicates (filter, assert; not match)

- text-re <pattern>
- text-starts <value...>
- text-ends <value...>
- text-contains <value...>

### Document predicates (filter, assert; not match)

- css <selector> — child element exists
- xpath <selector> — child element exists (all backends; JS uses `document.evaluate`)

### Length predicates (assert-only)

- len-eq <value...>
- len-ne <value...>
- len-gt <value>
- len-lt <value>
- len-ge <value>
- len-le <value>
- len-range <start> <end>

### Regex predicates (assert-only)

- re-any <pattern> — at least one list element matches
- re-all <pattern> — all list elements match

### Numeric predicates (assert-only)

- gt <value>
- lt <value>
- ge <value>
- le <value>

## JSON schemas

```kdl
json Author {
    name str
    slug str
}

(array)json Quote {
    tags (array)str
    author Author
    text str
}
```

Field types: str, int, float, bool, null, <RefName>.
Modifiers: (array)type for arrays, type? for optional, @omitempty for keys that may be absent, @skip to exclude from output.
Alias: `field-name type "original-key"`.

Usage: jsonify <SchemaName> [path="dotted.path"]

Block defines can be used inside json blocks. A bare define name (no args) expands its children as json fields:

```kdl
define PET-CORE {
    id int
    name str
    species str
}

json Pet {
    PET-CORE
    owner str?
}

(array)json PetList {
    PET-CORE
    adopted bool
}
```

## @request

Optional struct-level directive. Two modes:

1. **HTML-scraping struct** — single `@request` (no `name=`), parser takes the fetched HTML.
2. **`(rest)struct`** — typed REST client with multiple methods. Each `@request` requires `name=<kebab-id>` and `response=<SchemaName>`. Returns Result values, never throws.

Embeds a raw HTTP request or POSIX curl command. At codegen time the
converter parses it and emits a `fetch()` classmethod. The parser module
itself remains transport-agnostic — for HTML structs it still accepts one
HTML page.

### Formats

curl:
```kdl
@request """
curl 'https://example.com/{{slug}}'
"""
```

Raw HTTP:
```kdl
@request """
GET /catalogue/page-{{page-num}}.html HTTP/1.1
Host: example.com
Accept: text/html
"""
```

### Placeholders

`{{name}}` becomes a keyword-only parameter in `fetch()`, converted to snake_case.
Placeholder names must be **lowercase**: `[a-z][a-z0-9_-]*`.
UPPER_CASE `{{NAME}}` is reserved for define references (see `## define`).
No placeholders → static request, `fetch(cls, client)` only.

**Typed placeholders:** `{{name[:type][[]][?][|style]}}`
- `name` must be lowercase `[a-z][a-z0-9_-]*`
- `type` ∈ `str|int|float|bool` (default: str)
- `[]` marks array; `?` marks optional (`T | None = None`)
- `style` ∈ `repeat|csv|bracket|pipe|space` (arrays only; default: repeat)
- Examples: `{{id:int}}`, `{{q:str?}}`, `{{tags:int[]?|csv}}`, `{{tags[]|bracket}}`
- `[]` and `?` forbidden in URL path; style requires `[]`.

### Optional properties

- `name=<kebab-id>` — method name; required for `(rest)struct`, optional for HTML struct (only if multiple).
- `response=<SchemaName>` — JSON schema for 2xx body; required for `(rest)struct`.
- `doc="..."` — method docstring.
- `response-path="a.b.c"` — dot-notation path into JSON response body to extract HTML string
- `response-join="\n"` — join separator when response-path resolves to list[str]

```kdl
@request response-path="payload.html" """
POST /api HTTP/1.1
Host: example.com
Content-Type: application/json

{"id": "{{id}}"}
"""
```

### define with @request

Scalar define can be used as the @request argument:
```kdl
define BASE-URL="https://example.com"
define MY-REQ="curl {{BASE-URL}}/search?q={{query}}"
struct Foo {
    @request MY-REQ
    ...
}
```

Case convention separates define references from request parameters:
- `{{BASE-URL}}` (UPPER) → resolved at parse time from define
- `{{query}}` (lowercase) → becomes a runtime parameter in `fetch()`

### CLI flag

`--http-client` selects the generated HTTP client:
- Python targets: `httpx` (default; emits both `fetch()` and `async_fetch()`) | `aiohttp` (async-only) | `requests` (sync-only)
- JS target: `fetch` (default) | `axios`

Without `--http-client`, `@request` is ignored and no `fetch` method is generated.

## @error

Error response mapping for `(rest)struct`.

```kdl
(rest)struct Api {
    @error 404 ApiError
    @error 404 ApiError error
    @error 200 ActionResponse success=#false
    @error 200 ApiError error detail="msg"
}
```

### Arguments (positional, required)

- `<status>` — HTTP status code [100..599]
- `<SchemaName>` — json schema reference for deserialized error body

### Key presence checks (positional, optional)

Additional positional args after SchemaName check that keys exist in the JSON body:

```kdl
@error 404 ApiError error detail
```

Triggers when status=404 AND `_body` contains both `error` and `detail` keys.

### Value conditions (properties, optional)

KDL properties after the positional args are field=value conditions checked against the parsed JSON body:

- Keys are dot-paths (e.g. `response.success`, `data.0.type`)
- All conditions must match (AND logic)
- Covers the corner case where the same status code is used for normal and error responses

### Mixing both

Positional keys and property conditions can be combined:

```kdl
@error 404 ApiError error detail="msg"
```

Triggers when status=404 AND `'error' in _body` AND `_body.detail == "msg"`.

A key must not appear in both positional args and properties (lint error).

## CLI

```bash
# generate parser code
ssc-gen generate python schema.kdl -L bs4 -o out/
ssc-gen generate python schema.kdl -L lxml -o out/
ssc-gen generate python schema.kdl -L parsel -o out/
ssc-gen generate python schema.kdl -L slax -o out/
ssc-gen generate js schema.kdl -o out/
ssc-gen generate go schema.kdl -o out/

# with @request support (REST/HTTP codegen)
ssc-gen generate python schema.kdl -L bs4 -o out/ --http-client httpx

# extract helpers into separate runtime module (-R), custom name (-rn)
ssc-gen generate python schema.kdl -L bs4 -o out/ -R -rn my_runtime

# lint/validate schema (text or JSON for LLM pipelines)
ssc-gen check schema.kdl
ssc-gen check schema.kdl -f json

# run struct against HTML and print JSON
ssc-gen run schema.kdl:StructName -i page.html -L bs4

# verify selectors match elements
ssc-gen health schema.kdl:StructName -i page.html

# HTML reconnaissance (regex on text/attrs, CSS intersect, navigation, --discover)
ssc-gen scout -i page.html --text '\$\d+\.\d{2}' -f json
ssc-gen scout -i page.html --discover -f json

# print version
ssc-gen version
```

Languages: `generate python`, `generate js`, `generate go`.
HTML libraries (`--lib / -L`, Python only): `bs4` (default), `lxml`, `parsel`, `slax`.
HTTP clients (`--http-client`): Python — `httpx` (default) | `aiohttp` | `requests`; JS — `fetch` (default) | `axios`.

### `scout` — HTML reconnaissance

Probe raw HTML with regex on text/attribute values (CSS alone cannot
express this). Useful for picking selectors before writing a `.kdl` schema
or for one-off extraction.

```bash
# regex on text — find prices
ssc-gen scout -i page.html --text '\$\d+\.\d{2}' --fields path -f json

# regex on attribute value — find product hrefs
ssc-gen scout -i page.html --attr 'href=~^/product/\d+' -f json

# CSS intersect + climb to parent container
ssc-gen scout -i page.html --css ".price" --up 2 --fields path -f json

# one-off extraction (no .kdl needed)
ssc-gen scout -i page.html --css ".product-card" --fields attr.data-id,text -f json

# pipe via stdin
curl -s https://example.com | ssc-gen scout --attr 'class=~\bbtn\b' -f json

# count only (exit 0 on match, 1 on no match, 2 on error)
ssc-gen scout -i page.html --tag img --attr alt -v -c
```

Filters (AND-combine): `--text REGEX`, `--attr NAME[=VAL|=~REGEX]`, `--tag NAME`, `--css SEL`.
Modifiers: `-I` ignore-case, `-F` fixed strings, `-v` invert.
Navigation: `--up N`, `--down N`, `--next N`, `--prev N` (applied in order, deduped by tag identity).
Output: `--fields path,tag,text,html,attrs,classes,index,line,attr.NAME` (default `path,tag,text`).
Pagination: `--limit N` (default 50), `--offset N`, `--snippet LEN` (default 200).

`--discover` — overview mode: returns tag/class/id stats, data-* attrs, and
repeating containers (list-struct candidates with common_descendants field
hints). Ignores all filters and navigation. Single-call replacement for
blind selector probing.

```bash
ssc-gen scout -i page.html --discover -f json
```
