# 08. Scout — разведка и дистилляция HTML

**Версия DSL:** 2.1
**Последнее обновление:** 2026-11-01 (редизайн `scout`: обзор по умолчанию, 3 движка разведки, auto-zoom и `<-- MATCH`)

`ssc-gen scout` — единый инструмент структурной разведки и дистилляции HTML перед написанием `.kdl` схемы. За один вызов он очищает страницу от технического шума (`<svg>`, `<style>`, `<noscript>`, `<template>`, HTML-комментарии, пустые `<div>`-обёртки), отфильтровывает утилитарные и сгенерированные классы (Tailwind/Bootstrap, CSS-in-JS хэши `css-*`, `sc-*`, `svelte-*`, транзиентные state-классы `active`, `odd`, `even`) и возвращает **проверенные по DOM-дереву** CSS-селекторы, готовые к вставке в `.kdl`.

---

## Первый вызов — полный обзор страницы по умолчанию

Запуск `ssc-gen scout` без фильтров сразу выполняет полную структурную дистилляцию страницы (режим `overview`):

```bash
# Компактный текстовый дайджест (~2–3K токенов, оптимизирован для чтения и LLM)
ssc-gen scout -i page.html

# Полная структурированная сериализация ScoutResult в JSON
ssc-gen scout -i page.html -f json

# Отключить лимиты сжатия по умолчанию (показать все списки, поля, ключи и JSON-коллекции)
ssc-gen scout -i page.html --full
```

> **Примечание о совместимости:** флаг `--discover` сохранён как устаревший no-op алиас, поэтому старые вызовы `ssc-gen scout -i page.html --discover` продолжают работать без ошибок.

В начале текстового отчёта выводится глобальный маркер:
`# sample_normalized: true (whitespace collapsed; not verbatim)` (в JSON — `"sample_normalized": true`). Все текстовые примеры (`samples`) нормализованы через схлопывание пробелов (`get_text(" ", strip=True)`), поэтому не пишите регулярные выражения в `.kdl`, завязанные на сырые переводы строк или множественные пробелы из `sample`.

По умолчанию (без `--full`) действуют лимиты сжатия:
- До **7** развёрнутых повторяющихся списков (`repeating_lists`), до **25** полей на список, до **3** уникальных примеров текста (до 80 символов) на поле.
- До **5** таблиц и блоков «ключ — значение» (`kv_blocks`), до **25** ключей в каждом.
- До **5** встроенных JSON-сигналов/коллекций (`embedded_json`), до **20** полей в каждой коллекции.

## Три движка разведки и секции отчёта

Отчёт `ssc-gen scout` состоит из сводки страницы и трёх специализированных движков:

### 1. `=== PAGE SUMMARY ===` (`page_summary`)

Краткая сводка документа:
- `title` и `h1` — заголовок страницы и первый `<h1>`.
- `has_embedded_json` — найден ли встроенный JSON.
- `has_kv_blocks` — найдены ли таблицы или блоки «ключ — значение».
- `repeating_list_count` и `navigation_list_count` — число обнаруженных списков данных и свёрнутых списков навигации.

### 2. `=== EMBEDDED JSON ===` (`embedded_json`)

Движок поиска встроенного JSON сканирует все теги `<script>` (`application/ld+json`, `application/json`, все присваивания `var`/`let`/`const`/`window.X = ...`, вызовы `.push({...})` и распакованные строки `JSON.parse("...")`) и JSON-атрибуты HTML-элементов в цикле через стандартный `json.JSONDecoder().raw_decode()`. Это гарантирует 100% совместимость со строгим RFC 8259 JSON, который ожидают оператор `jsonify` и генерируемые JSON-проекторы во всех целевых языках.

- Тривиальные объекты (менее 2 ключей и без вложенных коллекций, например `{"env": "prod"}`) отбрасываются.
- Каждый JSON-пейлоад рекурсивно обходится (до глубины 8) для поиска массивов объектов (`kind: "array"`) и словарей данных (`kind: "object"`).
- Для каждого сигнала возвращаются:
  - `kind` (`"script"` | `"attr"`) и `subtype` (`"json-ld"`, `"json-mime"`, `"js-var"`, `"json-parse"`, `"js-push"`, `"bare-json"`, `"attr-json"`).
  - `selector` — проверенный CSS-селектор элемента.
  - `kdl_hint` — готовый KDL-пайплайн для извлечения (например, `css "script#__NEXT_DATA__"; raw inner; jsonify Schema` или `css "#app"; attr "data-state"; unescape; jsonify Schema`).
  - `collections` — список найденных коллекций с точным GJSON-путём `path` (`""` для корня или, например, `"props.pageProps.items"` для `jsonify Schema path="props.pageProps.items"`), количеством элементов `count` и списком `fields` (`name`, выведенный тип `str`, `int`, `float`, `bool`, `str?`, `array`, `object` и `samples`).

### 3. `=== KEY-VALUE & TABLES ===` (`kv_blocks`)

Движок таблиц и спецификаций находит как классические `<table>`, так и вёрстку характеристик без таблиц:
- `kv_table` — двухколоночные таблицы характеристик (кандидаты в `(table)struct` и `(dict)struct`).
- `dl` — списки определений `<dl>/<dt>/<dd>` (кандидаты в `(table)struct` и `(dict)struct`).
- `kv_rows` — повторяющиеся двухколоночные строки `<div>` или `<li>`, где левый дочерний элемент содержит короткую уникальную метку, а правый — значение (кандидаты в `(table)struct` и `(dict)struct`).
- `table_list` — таблицы данных с горизонтальной шапкой `<th>` ($\ge 2$ колонок) и строками `<td>` (кандидаты в `(list)struct`).

Для каждого блока возвращаются проверенные селекторы:
- `container_selector` $\to$ для `@table { css "..." }`.
- `rows_selector` $\to$ для `@rows { css-all "..." }` (или `@split-doc { css-all "..." }`).
- `key_selector` и `value_selector` $\to$ относительные селекторы ключа и значения внутри строки для `@match` и `@value`.
- `entries` (пары `key` и `sample` для `match { eq "..." }`) либо `headers` и `columns` (с селекторами колонок `td:nth-of-type(k)` для `table_list`).

### 4. `=== REPEATING LISTS & DOM SKELETON ===` (`repeating_lists`, `navigation_lists`)

Движок повторяющихся списков и свёрнутого скелета DOM находит кандидатов для `(list)struct`:
- **Структурная кластеризация и `outliers`:** соседние элементы внутри родителя группируются по имени тега и общим семантическим классам либо по структурному сходству тегов-потомков ($\text{Jaccard} \ge 0.5$). Если первая карточка имеет модификатор (`class="card featured"`), она не выпадает из списка; одиночные чужеродные вставки внутри контейнера (например, `<div class="ad-banner">` между карточками товаров) изолируются в список `outliers`.
- **Ранжирование и фильтрация навигации:** списки сортируются по информационной плотности (число уникальных полей и разнообразие текста). Навигационные списки (`<nav>`, `<header>`, `<footer>` или элементы из одной ссылки `<a>`) сворачиваются в однострочные комментарии `<!-- nav-list xN: selector [...] -->` (`navigation_lists`).
- **Union Archetype (объединённый архетип карточки):**
  - `selector` — проверенный CSS-селектор карточек для `@split-doc { css-all "..." }` со статусом `selector_stability` (`"stable"` | `"fragile"`).
  - Одиночные цепочки обёрток схлопываются через ` > ` (например, `h3 > a`).
  - Для каждого поля указывается относительный селектор `css`, покрытие `[present/total]` (например, `[24/24]` или `[5/24, optional]` — прямой сигнал добавить `fallback #null`), `samples` текста и `attr_samples` (`href`, `src`, `content`, `value`, `data-*`).
  - **Разрешение однотипных соседей внутри карточки (`kind`):**
    - `scalar` — одиночное поле (`css "..."`).
    - `positional` — если тег с тем же классом повторяется внутри карточки фиксированное число раз ($\le 6$, например 3 тега `<span class="spec">` для года, двигателя и КПП), `scout` автоматически разделяет их на позиционные слоты `:nth-of-type(1)`, `:nth-of-type(2)`, `:nth-of-type(3)` с отдельными примерами для каждого слота.
    - `array` — если число повторений внутри карточки варьируется (например, от 1 до 5 бейджей), поле помечается как `css-all="..." [array min..max items]`.

## Режим приближения (Zoom-in Mode) и `<-- MATCH`

Передача любого из фильтров (`--text`, `--attr`, `--css`, `--tag`) переключает `ssc-gen scout` в режим **Zoom-in** (`mode: "zoom"`). Вместо ручной навигации по дереву (старые флаги `--up`, `--down`, `--next`, `--prev`, `--fields` удалены) движок сам находит контекст совпадения:

| Флаг | Форма | Описание |
|---|---|---|
| `--text REGEX` | regex / literal | Поиск по нормализованному тексту поддерева (`get_text(" ", strip=True)`), включая текст, разбитый между инлайн-тегами (`<span>1 299</span> <span>₽</span>`). Выбирает **самый глубокий минимальный тег**, охватывающий совпадение |
| `--attr NAME` | presence | Атрибут `NAME` присутствует на элементе (флаг можно указывать несколько раз) |
| `--attr NAME=VAL` | exact | Точное совпадение значения атрибута |
| `--attr NAME=~REGEX` | regex | Регулярное выражение по значению атрибута |
| `--tag NAME` | exact | Фильтр по имени HTML-тега |
| `--css SEL` | css | Ограничение кандидатов CSS-селектором |
| `-I` / `--ignore-case` | modifier | Регистронезависимый поиск для `--text` и `--attr NAME=~REGEX` |
| `-F` / `--fixed` | modifier | Трактовать шаблон в `--text` и `--attr NAME=~REGEX` как буквальную подстроку (экранирует метасимволы regex) |

Все указанные фильтры комбинируются через логическое **И**.

### Автоматическое расширение контейнера

Для каждого найденного минимального узла `scout`:
1. Проверяет, находится ли узел внутри одного из повторяющихся списков (`repeating_lists`) или таблиц/KV-блоков (`kv_blocks`). Если да — выводит архетип этого списка/таблицы и помечает совпавшее поле маркером `<-- MATCH` (в JSON — `"matched": true`).
2. Если узел лежит вне списков и таблиц (например, заголовок или цена в карточке одного товара на детальной странице) — автоматически поднимается до охватывающего семантического блока (до 3 уровней вверх до `main`, `article`, `section` или тега с `id`/семантическим классом) и рендерит его скелет в секции `=== ZOOM MATCHES ===` (`zoom_matches` в JSON) с отметкой `<-- MATCH` на целевых полях.

## Примеры

```bash
# 1. Первый вызов — полный обзор страницы (текстовый дайджест для чтения или LLM)
ssc-gen scout -i page.html

# 2. Полный обзор в формате JSON
ssc-gen scout -i page.html -f json

# 3. Полный обзор без лимитов усечения
ssc-gen scout -i page.html --full

# 4. Zoom-in по тексту (находит минимальный узел, даже если текст разбит по <span>,
#    раскрывает родительскую карточку и помечает поле через <-- MATCH)
ssc-gen scout -i page.html --text '\$\d+\.\d{2}'
ssc-gen scout -i page.html --text "1 299 ₽" -F

# 5. Zoom-in по атрибуту (regex на href)
ssc-gen scout -i page.html --attr 'href=~^/product/\d+' -f json

# 6. Комбинация CSS-селектора, тега и регистронезависимого текста
ssc-gen scout -i page.html --css ".product-detail" --tag span --text "в наличии" -I

# 7. Чтение HTML из stdin
curl -sL https://example.com | ssc-gen scout
```

## Exit codes

- `0` — успех (в режиме обзора `overview`, либо в режиме `zoom`, когда найдено хотя бы одно совпадение: `matched > 0`).
- `1` — в режиме `zoom` (переданы фильтры `--text`, `--attr`, `--tag` или `--css`) совпадений не найдено (`matched == 0`).
- `2` — ошибка входных данных или фильтра (пустой HTML на входе, невалидный CSS-селектор или синтаксическая ошибка в регулярном выражении `FilterError`).
